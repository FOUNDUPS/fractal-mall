# Research Moshpit

The Action Queue Mosh Pit owns live work. The manuscript owns prose, sources and substantive review. GitHub owns public, revisioned methods and cleared evidence. Give each task one persistent FQ identifier. Use cross-links when a task also appears as a Mall tile.

## Triage a discovery

Apply the [notebook WSP catalog and triage](../../WSP.md). Record capability, write target, dependency, acceptance evidence and WSP_15 rationale on the live Moshpit entry. Choose do, route, defer or ask 012. Use `FOUNDUPS/fractal-mall` for experiment builds and fixtures. A request to edit or integrate an upstream system stays deferred pending separate scope.

## Claim and assign

Read the current task row and open comments. A proposed assignment names a capability lane. The session accepting it signs **0102**, adds its short claim ID, claim time, expiry (60 minutes in JST), concrete deliverable and acceptance condition. Move OPEN to CLAIMED with a revision guard if available and read back ownership. On conflict, refresh before changing the row. If a lease has expired, check for intervening work and log reassignment while preserving prior contributions.

## Submit and verify

Move the ticket to IN_REVIEW with the passage, source revision, evidence, limits and next reviewer capability. A different session reproduces the check, replies with its disposition and marks VERIFIED_COMPLETE if it passes. A failed check reopens the ticket with the exact missing evidence. A blocked ticket records the dependency and next observable action. Read-only participants return a receipt for the coordinator to attach.

## Record the round

Under the effective JST date, put the newest event first. Keep one brief event with timestamp, ticket/claim, action, result, evidence link and next question. Preserve superseded verdicts and link the replacement. Private session diagnostics belong in the appropriate separate learning log. Release decisions remain with 012.

## Close an MP line

Link each discovery or blocker to an existing MP line, or create a numbered line when its question is new. Link its FQ execution ticket. Strike through the completed task description and leave the 0102 signature, claim ID, JST time and evidence link readable. Keep a partial item open and record its verified part. A viewer can return the same signed patch without changing the queue.
